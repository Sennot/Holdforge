# HoldForge 0.2.2-beta.3

**GD 2.2081 / Geode 5.10.1 / Windows x64.** Импорт Silicate `.slc` v2/v3,
запись траектории и генерация hold-версии обычными объектами уровня.

## Возврат после Record — исправление beta.3

В beta.2 любое несовпадение строки уровня скрывало выбранный макрос. Из-за
этого после Record → Save and Exit → Play → редактор окно могло снова
требовать Import. В beta.3 выбор макроса и пригодность записи проверяются
отдельно: при возврате в тот же уровень макрос, запись и результат прогона
остаются доступны. Неудачный прогон показывает свою ошибку, а не Import.

Сравнение содержимого больше не зависит от порядка полей, написания чисел
X/Y/rotation (10 и 10.0), слоёв редактора 20/61 и страницы цветов kS39.
Порядок ОБЪЕКТОВ, координаты, группы, режимы и неизвестные свойства сохраняют
значение: реальные правки не разрешают использовать неподходящую траекторию.
Повторяющиеся ключи и некорректные записи сравниваются буквально.

Ожидаемый процесс после успешной записи: **вернуться в HF → Analyze → Create**.
Если содержимое действительно изменилось, макрос остаётся выбранным; кнопка
Record начинает новую запись текущего исходника без повторного выбора файла.
Если уровень не менялся, сначала Export logs: отчёт укажет номер записи
(0 — заголовок, 1+ — объект), свойство и ограниченные значения до/после.
Полная строка уровня в этот отчёт не добавляется.

Новые записи используют стабильный ключ с префиксом `level-v1-`; формат самой
траектории остаётся HFTRACE3. Старые записи загружаются только при точном
совпадении их прежнего хеша с текущим исходником. После обновления может
понадобиться одна новая запись; удалять старые кэши или объекты для этого не нужно.

Автономные тесты: **42 745 проверок и 2 000 мутаций повреждённых входов**,
ASan/UBSan, строгие предупреждения компилятора. Проверены возврат после
пересохранения, сохранение макроса при реальном изменении, защита другого
уровня, восстановление состояния после Create, отказ при изменении геометрии
и загрузка траектории с тем же содержимым. Это проверки ядра; Windows/GD
в этой среде не запускались. Они не подтверждают поведение сторонних модов.

## Исправления 0.2.2

- Исправлен ID входного портала: **2902**, а **2064** — оранжевый выход.
  Предыдущая версия ошибочно использовала выход как вход. Конечная точка
  теперь тоже штатный выход 2064 с NoTouch. ID 2065 (частицы) больше не
  вызывает ложное предупреждение о телепортации.
- `portal_probe` в отчёте показывает созданный ID, тип, признак выхода и
  размеры коллизии. Проверка типа сохраняется и не обходится принудительным cast.
- **Manual dual sections** — обработать обычные места модом, дуалы построить
  вручную: включить оба управления на входе, не ставить макросные Options
  внутри, на выходе восстановить состояние макроса. Переходы берутся из записи.
  Режим перекрывает Invisible dual auto / Shared P1 gates only и не влияет на 2P.
- Независимый `last-stage.json` фиксирует загрузку/сброс уровня и создание
  объектов, даже когда основной журнал достиг лимита. При следующем запуске
  старая отметка сохраняется в `previous-stage.json` и попадает в Export logs.

Краш с `PlayerObject::copyAttributes` через Spout / More Icons по присланному
стеку **не воспроизведён и не объявляется исправленным**. Для проверки сначала
отключить Spout Clean Feed, полностью перезапустить GD и повторить загрузку;
при сохранении краша — отдельно проверить More Icons. Новые отметки помогут
отделить падение внутри исходной загрузки от действий HoldForge после неё.

## Невидимое авто для обычного дуала

Настройка **Invisible dual auto (beta)** включена по умолчанию. Для второго
персонажа обычного дуала генератор ставит невидимые контактные телепорт-порталы
вдоль записанного пути. Это не переключение уровня в 2 Player Mode.
Первый персонаж использует Options, управление второго блокируется, его путь
приближённо воспроизводят объекты. Алгоритм принимает Cube, Ship, UFO, Ball,
Wave, Robot, Spider и Swing, включая смешанные пары и мини-размер.

**Это экспериментальная схема, а не подтверждённая поддержка всех дуалов.**
Проверены автономные тесты записи, сериализации и планирования для 64 пар форм.
Windows-сборка и прохождение в GD здесь не запускались. Телепортация не
воспроизводит нажатия, вращение, гравитацию и все побочные эффекты оригинала.
В частности, связанные переключения гравитации, орбы, триггеры при касании,
телепортация паука и порядок столкновений могут потребовать ручной правки.

Объекты невидимы через Hide, эффекты/частицы выключены. NoTouch используется
только для конечных маркеров, а не для рабочих порталов. Каждый портал
включается на один физический шаг через Toggle; следующая точка служит целью
предыдущего портала. Ignore X сохраняет горизонтальную координату. Static Force
0 сбрасывает накопленную вертикальную скорость. Гравитацию портал не меняет,
чтобы не вносить неявные связанные перевороты первого персонажа.

Генерация не использует runtime-нажатия, изменение координат хуками или noclip.
Все управляющие объекты сохраняются в уровне. После успешного теста в чистой
игре такой результат не требует установленного HoldForge у других игроков.

## Быстрый запуск

1. Замени исходники репозитория целиком, включая `.github`, `src`, `CMakeLists.txt`
   и `mod.json`. Собери через **Actions → Build HoldForge**. Установи `.geode`
   из артефакта **HoldForge-Win64**, сохрани `.pdb` для диагностики краша.
2. Открой **исходную копию без предыдущих Options/автообъектов**. В HF нажми
   **Import .slc → Record**. Оба offset — 0. Invisible dual auto — ON.
3. Закрой HF → **Save and Exit → обычный Play**. Воспроизведи этот же макрос
   в Silicate от начала до завершения, без practice, StartPos и noclip.
   **Save and Play не обязателен.** Не закрывай саму игру между действиями.
4. Вернись в редактор → **HF → Analyze → Create**. Импортировать макрос повторно
   не нужно. Генерация имеет одну Undo-операцию; перед вставкой сохраняется backup.
5. **Verify** → выключи playback макроса и noclip → **Save and Exit → Play**.
   Держи одну кнопку непрерывно от начала. В 2 Player Mode нужно держать оба ввода;
   невидимые автообъекты в этом режиме не создаются.
6. Вернись в HF за результатом. При ошибке — **Export logs**, отправь JSON.
   Перед публикацией проверь сохранённый уровень с выключенными HoldForge,
   макросом и модами, меняющими физику/управление.

**Совпадающую HFTRACE3 из 0.2.1 можно использовать повторно** для того же исходного уровня
и макроса. Старые HFTRACE2 хранили только клики и требуют новой записи.
HFTRACE3 сохраняет каждый шаг 240 TPS, обе позиции, формы, размеры, скорости,
гравитацию и состояние управления. Кэш привязан к точному макросу и исходному
уровню. Копию уровня разработчику передавать не нужно. После смерти/ошибки снова
нажми Record или Verify; частичный прогон не считается готовым.

## Если дуалы делаешь сам

1. Включи **Manual dual sections**. Invisible dual auto можно оставить OFF;
   ручной режим в любом случае имеет приоритет. Require recording / Strict 240
   — ON, оба offset — 0, Backup — ON, Allow existing controls — OFF.
2. Запиши исходный уровень через Record → Save and Exit → Play с макросом.
   Если уже есть подходящая HFTRACE3 для этого макроса и исходной копии,
   повторная запись после обновления не требуется.
3. Analyze → Create, затем поставь свои невидимые блоки/пады в дуалах.
   Внутри секций мод оставляет управление включённым: строй под непрерывный hold.
   Границы и сами невидимые конструкции нужно проверить в игре.
4. Проверяй обычным Play, макрос выключен. Для ручного режима кнопка Verify
   объясняет, что сравнение с исходной траекторией недоступно. Правки меняют
   траекторию; после них прежняя точная проверка не должна выдавать ложный успех.
   Перед публикацией протестируй с выключенным HoldForge.

## Ограничения и понятные ошибки

- **AUTO_P1_OVERLAP:** портал мог бы задеть первого персонажа. Проверяется
  область его движения с запасом, поскольку обычный контактный портал нельзя
  считать исключительно «для P2». В таком месте нужны ручные автообъекты;
  вся пачка отменяется, дырки в маршруте молча не оставляются.
- **AUTO_OBJECT_LIMIT / AUTO_GROUP_LIMIT:** нужны примерно 960 объектов и
  240 групп на секунду дуала. Конечная точка добавляется на каждый участок.
  Лимит объектов можно поднять в настройках; лимит групп GD — 9999.
  Используемые и даже только упомянутые ID резервируются консервативно.
- **AUTO_PORTAL_TYPE / EDITOR_VERIFY:** GD не распознала ожидаемый объект или
  параметры. Вставка отменяется/откатывается; JSON содержит данные для исправления.
- **PLAN_SAME_FRAME:** swift остаётся неподдерживаемым для Options первого
  персонажа. Ошибка теперь показывает точный кадр и время. Макрос не изменяется.
- Классические уровни с движением вправо и 240 TPS. Reverse, TimeWarp,
  повороты и нестандартная физика не становятся поддерживаемыми от включения
  Experimental timeline. Запись останавливается при пропуске шагов/обратном X.

## Verify и диагностика

В обычных местах проверяются позиции и формы на кадрах макроса, допуск 0.5
единицы. При невидимом авто каждый шаг дуала сравнивается с записью: первый
персонаж — 0.5, второй — 6 единиц, режим и dual должны совпасть. Допуск — это
условие проверки, а не обещание точности генератора.

Проверяются прохождение всех Options, фактические активации всех авто-порталов
именно вторым персонажем и одно непрерывное удержание. Сырой held-флаг больше
не сравнивается с макросом: у hold и у автообъектов он закономерно другой.
Любая видимая хуку попытка смерти отменяет проверку. Чужие хуки могут скрывать
события, поэтому тест без модов остаётся необходимым.

JSON schema 6 содержит `portal_probe`, `manual_duals`, `last_stage`,
`previous_process_stage_json`, `invisible_dual_auto`, `auto_anchor`,
`auto_portal_activated` (до/после, игрок, цель), `auto_first_mismatch`,
`auto_wrong_player`, `auto_incomplete`, `object_readback_error` и максимум
отклонения. Логи ограничены настройкой Diagnostic event limit.

## Настройки кратко

| Настройка | Назначение |
|---|---|
| Manual dual sections | Оставить дуалы для ручных автообъектов; приоритет над Invisible dual auto |
| Invisible dual auto (beta) | Невидимые объекты по новой записи для обычного дуала |
| Require recorded trajectory | Требовать реальную запись; оставь ON |
| Strict 240 TPS | Отклонять несовместимую частоту физики; оставь ON |
| Timing / Position offset | Сдвиг только приблизительного режима; для записи оба 0 |
| Trigger row Y / Generated editor layer | Расположение Options и слой всей генерации |
| Maximum generated objects | Общий лимит Options, порталов, маркеров и Toggle |
| Backup before import | Сохранить исходную строку уровня перед вставкой |
| Shared P1 gates only | Старый диагностический вариант без авто; авто его перекрывает |
| Experimental timeline | Разрешить попытку на сложной механике, без гарантии совместимости |
| Allow existing control triggers | Разрешить конфликтующие Options; обычно OFF |
| Debug / Runtime / Mapping / Objects / Mods | Журнал, игровые события, размещение, строки объектов, версии модов |

## Сборка и тесты

Workflow закрепляет Geode 5.10.1 и bindings
`7f6c2a75742856de88dad354e576dcff8a28e881`. Сначала выполняются тесты ядра,
затем сборка Win64 и выгрузка `.geode`/`.pdb`.

```sh
cmake -S . -B build-tests -DHOLDFORGE_CORE_ONLY=ON
cmake --build build-tests --parallel
ctest --test-dir build-tests --output-on-failure
```

Тесты ядра не являются эмуляцией GD. Реальная проверка всех форм, гравитации,
орбов и переходов выполняется через Verify и затем без HoldForge.
