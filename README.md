# HoldForge 0.2.2-beta.4

GD 2.2081 / Geode 5.10.1 / Windows x64. Импорт Silicate `.slc` v2/v3,
запись траектории и генерация hold-версии штатными объектами уровня.

## beta.4: проверки совместимости больше не блокируют работу

Исправлена ложная ошибка RUN_DAMAGE: вызов `destroyPlayer` сам по себе не
доказывает смерть и не определяет наличие noclip. Теперь это DAMAGE_CALLBACK
warning. Запись и Verify продолжаются; мод не изменяет физику и не предотвращает
настоящую смерть игрока. Настоящий сброс попытки начинает новую запись.

- Несовпадение уровня, режима 2P, таймингов, существующие Options, StartPos,
  practice, неполная запись и ошибки Verify дают предупреждения.
- Неполные записи сохраняются. Для отсутствующих кадров используется
  приблизительная карта времени редактора. Analyze/Create работают без Record.
- Некорректный кэш не отменяет Import: выбранный макрос остаётся доступен.
- Не-240 TPS принимается. Swift-события одного кадра сводятся к конечному
  состоянию: сам короткий импульс этим не воспроизводится. Left/Right и
  restart/death/bugpoint-маркеры пропускаются с предупреждением.
- Невидимое авто допускает пересечение с P1 и превышение настроенного количества
  объектов с предупреждением. Неразмещаемые интервалы пропускаются. Если всю
  схему построить невозможно (например, закончились группы или неверен тип
  портала), остаются Options, а пропуск явно указан в предупреждениях.
  В таком fallback блокировка P2 для авто не остаётся включённой навсегда.
- Повторный Analyze/Create разрешён. Существующие пачки автоматически не удаляются.
- Verify доходит до конца при расхождениях; результат с предупреждениями не
  объявляется подтверждённым совпадением. Verify можно запускать без эталона
  как наблюдение. Его результат не запрещает Create или обычную игру.
- Удалены настройки Strict 240 TPS, Require recorded trajectory, Experimental
  timeline и Allow existing control triggers: эти запреты больше не действуют,
  в том числе после обновления поверх прежних настроек.

Сохранены технические проверки: читаемый формат файла, конечные координаты,
существующий остановленный редактор, корректное создание объектов и Undo.
Если игра не смогла создать нужные объекты, повреждённая пачка откатывается.
Это не античит: проверки наличия noclip нет.

## Как пользоваться

1. Открой копию уровня → HF → Import `.slc`.
2. Для лучшей точности нажми Record, закрой HF → Save and Exit → обычный Play
   с тем же макросом Silicate. Save and Play не требуется.
3. Вернись в редактор → HF → Analyze → Create. Полный прогон предпочтителен,
   но выход раньше конца больше не отбрасывает всю запись. Без записи также
   можно сразу Analyze/Create, позиции будут приблизительными.
4. Для проверки нажми Verify, выключи playback макроса, Save and Exit → Play,
   удерживай ввод. В 2 Player Mode удерживай оба входа. Расхождения попадут в
   предупреждения и Export logs, прогон не отменится.
5. Одна операция Undo удаляет добавленную пачку. Перед публикацией проверь
   готовый уровень с выключенным HoldForge и модами, меняющими физику.

Макрос сохраняется при возврате в редактор и изменении уровня. Смена уровня
теперь тоже только предупреждает об использовании прежней записи. Для другого
макроса нажми Import. Новые записи имеют формат HFTRACE4 и хранят неполные
данные и предупреждения отдельно от старого строгого формата. Совместимые
HFTRACE3 загружаются; старые файлы не удаляются.

## Дуалы и настройки

Обычный dual использует общий P1-ввод; независимые P2-события относятся к
2 Player Mode. Invisible dual auto создаёт скрытые native touch portals
вдоль записанного P2-пути. Вход — **2902**, конечный оранжевый выход — **2064**.
2065 — частицы. Это приблизительная экспериментальная схема, а не доказанная
поддержка всех дуалов/смешанных форм: касания, гравитация и орбы могут отличаться.

- **Manual dual sections**: обычные места генерируются, в записанных дуалах
  управление включается и пропускаются макросные Options. Свои блоки/пады
  строишь вручную. Если неполная запись заканчивается внутри дуала, неизученный
  хвост не вырезается из макросных gates. В 2P режим не применяется.
- **Invisible dual auto**: скрытые порталы по доступным записанным шагам;
  Manual dual sections имеет приоритет. Примерно 960 объектов/секунду.
- **Shared P1 gates only**: диагностический вариант обычного dual; свойство
  P2 оставляется без изменений. Не является подтверждённым исправлением dual.
- **Timing offset**: сдвиг времени. При ненулевом значении используются позиции
  карты времени редактора, даже если запись загружена.
- **Position offset**: сдвиг Options по X, не перемещение записанных auto helpers.
- **Trigger row Y / Generated editor layer**: размещение Options в редакторе.
- **Object count warning threshold**: только предупреждение, без отмены Create.
- **Backup before import**: резервная строка уровня. Ошибка сохранения сообщает
  предупреждение, создание продолжается с Undo.
- **Advanced Debug**: журнал, входы, позиции, runtime-события, версии модов,
  строки объектов и ограничение размера отчёта. Export logs создаёт JSON.

## Сборка и проверка

Загрузи содержимое этого архива в корень репозитория. GitHub Actions запускает
автономные тесты, затем Windows-сборку. Артефакт **HoldForge-Win64** содержит
`.geode` и отладочные символы. SDK 5.10.1, bindings для GD 2.2081 закреплены
в `.github/workflows/build.yml`.

Автономные тесты: 42 771 проверка и 2 000 детерминированных мутаций.
Проверены парсер, генератор, неполные записи, HFTRACE3/4,
предупреждения и планирование дуалов под ASan/UBSan. Windows/GD здесь не
запускались. Снятие блокировок не доказывает точность физики; сценарии для
проверки в игре перечислены в `docs/IN_GAME_TESTS.md`.

Прежний краш с `PlayerObject::copyAttributes` через Spout / More Icons по
присланному стеку не воспроизведён и этой обновой не объявляется исправленным.
`last-stage.json` и предыдущая стадия включаются в Export logs для диагностики.
