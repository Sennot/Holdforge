# HoldForge 0.2.0-beta.1

Geode-мод для **GD 2.2081 / Geode 5.10.1 / Windows x64**. Преобразует
нажатия Silicate `.slc` v2/v3 в обычные Options Triggers.

В этой бете добавлены запись координат при воспроизведении макроса и сравнение
созданной hold-версии с записью. Удалена runtime-поправка 0.1.3: HoldForge больше
не вызывает press/release и не меняет управление игроками во время прохождения.
Созданные объекты сохраняются в уровне и не требуют HoldForge у аудитории.
**Это не доказывает корректность результата: обычный dual без runtime-поправки
ещё не подтверждён. Версию нужно проверить в игре перед публикацией уровня.**

## Быстрый старт

1. Обнови исходники в репозитории целиком, включая `.github`, `CMakeLists.txt`
   и `mod.json`. Удали старые `src/core/Calibration.*` и `HeldInput.hpp`, если
   копируешь поверх предыдущей версии. Собери через **Actions → Build HoldForge**.
   Из артефакта **HoldForge-Win64** установи `.geode`; `.pdb` сохрани на случай краша.
2. Открой исходную копию уровня без предыдущей генерации Options. Останови
   playtest, нажми **HF → Import .slc**. Оба offset оставь равными нулю.
3. **Record** → закрой HF → **Save and Play**. В Silicate воспроизведи этот же
   макрос с начала в normal mode, без StartPos, noclip и ручных нажатий.
   Исходный макрос должен полностью проходить исходный уровень.
4. После завершения вернись в редактор → **HF → Analyze → Create**.
   Повторно импортировать файл не нужно. Вставка имеет одну Undo-операцию.
5. **Verify** → отключи воспроизведение макроса и noclip → **Save and Play**.
   Держи P1 с начала до конца; в 2 Player Mode держи оба соответствующих ввода.
   Вернись в HF за результатом. При ошибке нажми **Export logs**.
6. Перед публикацией проверь сохранённый уровень с выключенными HoldForge,
   воспроизведением макроса и модами, меняющими физику/управление.

При смерти/несовпадении запись или проверка прекращается. Для новой попытки
снова нажми Record либо Verify. Не редактируй уровень между вооружением режима
и прогоном. Режимы используют **Save and Play**, не playtest внутри редактора.
Новый макрос или изменённый исходный уровень требуют новой записи.

## Что делает Record

Record наблюдает события Silicate в очереди физики и проверяет их кадры,
порядок, нажатия/отпускания и игрока относительно выбранного `.slc`.
Начало игрового времени относительно кадров определяется по первому событию;
последующие события должны соответствовать тому же сдвигу.

Для каждого события сохраняются физические позиции P1/P2, режимы, dual и
состояние удержания после обработки очереди. Визуально сглаженные координаты
спрайта не используются. X триггера выбирается внутри наблюдённого интервала
движения между соседними шагами с учётом округления при сохранении.
Это устраняет зависимость от приблизительной карты редактора и старого
постоянного сдвига −0.25; совпадение фаз Options и ввода проверяет Verify.

Только завершённая запись сохраняется в каталоге мода `trajectories/*.hftrace2`.
Она привязана к отпечаткам бинарника макроса и строки исходного уровня, а также
2 Player Mode. Старые ручные `.hftrace` больше не используются.
Уровень передавать разработчику для записи не нужно.

## Что проверяет Verify

В моменты записанных вводов сравниваются время, физические координаты,
режимы и удержание P1/P2, а также dual. Допуск координат — 0.5 единицы,
времени — четверть физического шага. Проверяются наблюдение всей пачки
Options и непрерывное физическое удержание. Попытка повреждения игрока,
видимая хуку, отменяет проверку даже при подавлении смерти другим модом.

При первом несовпадении `native_first_mismatch` содержит ожидаемое и фактическое
состояния и кадр. Verify ничего не корректирует в физике или уровне.
Успех означает совпадение в текущем окружении на проверенных кадрах, а не
доказательство полного совпадения каждого шага или независимости от других модов.
Чужой хук может скрыть от наблюдателя события. Финальный тест без модов нужен
для заявления, что публичная hold-версия работает самостоятельно.

## Options и dual

ID Options — **2899**. Property **165** управляет Disable P1 Control,
**199** — Disable P2 Control. Значения трёхсоставные:

| Значение | Смысл |
| --- | --- |
| `1` | Включить блокировку управления |
| `-1` | Снять блокировку управления |
| `0` | Не менять эту настройку |

Press макроса создаёт `-1`, release — `1`; до первого press управление блокируется.
Обычный dual по умолчанию использует парные P1/P2 gates. В 2 Player Mode потоки
независимы, одновременные события объединяются в один Options.

В старых логах доказано расхождение P2 в обычном dual. Предыдущая runtime-поправка
маскировала его ценой зависимости от HoldForge. Она удалена. В настройках есть
диагностический вариант **shared P1 gates only**, оставляющий property 199
неизменной; это гипотеза для сравнения в игре, **не подтверждённое исправление**.
Чтобы сравнить варианты, сделай Undo, закрой/открой HF, измени настройку и заново
Analyze → Create → Verify. Перезаписывать исходную траекторию не нужно.

## Настройки кратко

| Настройка | Назначение |
| --- | --- |
| Require recorded trajectory | Требовать полную запись; выключение разрешает приблизительную карту редактора |
| Strict 240 TPS | Ограничить приблизительный импорт 240 TPS; Record всегда требует 240 TPS |
| Timing offset / Position offset | Ручной сдвиг приблизительной карты; для записи оба должны быть 0 |
| Trigger row Y / Generated editor layer | Где разместить триггеры в редакторе |
| Maximum generated triggers | Предел размера пачки |
| Backup before import | Сохранить строку уровня до вставки в `backups` |
| Diagnostic: shared P1 gates only | Эксперимент с P1-only Options; не затрагивает независимый 2 Player Mode |
| Experimental timeline | Разрешить попытку на известных сложных механиках; поддержку этих механик не добавляет |
| Allow existing control triggers | Разрешить конфликтующие Options; обычно оставлять выключенным |
| Enable diagnostic journal | Журнал и экспорт событий |
| Log decoded macro inputs | Все разобранные события `.slc` |
| Log time-to-position mapping | Кадр/время/X и поля каждого создаваемого Options |
| Trace playtest inputs and triggers | Подробные события вне активного Record/Verify; может замедлять игру |
| Include generated object strings | Сериализация Options в событиях mapping |
| Include mod versions | Установленные моды и их версии |
| Diagnostic event limit | Ограничение объёма журнала и экспортируемых событий |

Record/Verify автоматически запрашивают нужные события при включённом diagnostic
journal. Для подробного отчёта достаточно стандартных настроек и **Export logs**.
После сбоя не делай новый Import до экспорта: Import начинает новую сессию журнала.
При краше сохрани `diagnostics/latest.jsonl` и crash log Geode; после перезапуска
журнал прошлой сессии называется `previous.jsonl`.

## Ограничения и проверка

- Поддерживается classic; platformer, Swift и press/release в одном кадре отклоняются.
- Нужна одна чистая попытка: Restart, Death, Bugpoint и Left/Right отклоняются.
- Запись требует стабильного времени 240 TPS и движения вперёд. Reverse,
  TimeWarp, dash, teleport и Player Control по умолчанию блокируются.
- Random/seed и изменения физики других модов в уровень не переносятся.
- После перезапуска игры завершённая запись загрузится при импорте исходного
  макроса на исходном уровне. Сессия проверки уже созданной пачки не сохраняется.
- В approximate-режиме Verify недоступен без записанной траектории.
- Исправление меню сохраняется: HF находится в собственном контейнере EditorUI,
  хука `EditorPauseLayer` нет. Совместимость с набором модов требует проверки.

Локально прошли **1600 проверок**, 2000 детерминированных мутаций входных данных,
ASan/UBSan и разбор присланного `.slc` с 412 событиями. Это тесты независимого ядра,
не Windows-сборка и не игровой прогон. LeakSanitizer отключён из-за ограничений среды.
Windows-сборку выполняет приложенный Actions workflow с закреплёнными SDK/bindings.

```sh
cmake -S . -B build-tests -DHOLDFORGE_CORE_ONLY=ON
cmake --build build-tests
ctest --test-dir build-tests --output-on-failure
```
