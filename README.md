# HoldForge 0.1.3 — .slc → hold-версия

**0.1.3: заменена неудачная поправка 0.1.2.** Общий hold берётся из
`handleButton`, с UI только как резервом до первого события. Парные Options
на Generated editor layer явно применяют press/release к P1 и активному P2;
уже удерживаемая кнопка повторно не нажимается. При входе в dual P2 получает
текущую блокировку и удержание. Независимый 2 Player Mode не затрагивается.
**Shared dual hold compatibility должна быть включена; HoldForge требуется
при игре.** Это runtime-поправка, не автономное исправление самой GD.

Для присланного `1.slc` подготовлен `calibration/1.hftrace`: координаты всех
412 событий из предыдущего полного прогона. Файл привязан к отпечаткам макроса
и исходного уровня. Это позволяет заменить приблизительную карту редактора
записанными позициями, не передавая копию уровня.

### Быстрая установка 0.1.3

1. Собери обновлённые исходники через Actions и установи `.geode`.
2. Скопируй `calibration/1.hftrace` **рядом с твоим `1.slc`**. При переименовании
   макроса имя `.hftrace` тоже должно совпадать.
3. Открой исходную копию уровня **без старой пачки Options**. Если удаляешь
   старую генерацию вручную, удаляй только её. Установи оба offset = 0.
4. Import `1.slc`: статус должен быть **Recorded positions ready**. Create.
   Старые триггеры обязательно заменить, иначе тайминги останутся прежними.
5. Отключи воспроизведение макроса, держи P1 с начала. HoldForge и Shared dual
   hold compatibility оставь включёнными. Для отчёта включи Runtime trace.

При `TRACE_LEVEL` текущая строка уровня отличается от исходной записи:
используй исходную копию/Undo. Профиль не применяется молча к другому уровню.
Файл калибровки содержит личные данные прогона и исключён из git через .gitignore;
для сборки он не нужен, используется локально рядом с макросом.

Место Options выбрано на 0.25 единицы левее записанного pre-input X, чтобы
пересечение происходило к исходной точке ввода и переживало округление GD.
Фаза обработки всё ещё требует игрового теста; нулевые смерти не подтверждены.

**Исправление 0.1.1:** удалён хук `EditorPauseLayer::customSetup` и кнопка из паузы.
Открытие перенесено в отдельный контейнер с кнопкой **HF** слева в редакторе;
контейнер добавляется после завершения инициализации. Во время паузы/playtest
кнопка скрыта. Это устраняет прежнее вмешательство HoldForge в структуру паузы;
исправление краша с BetterEdit требует проверки в игре. В логах теперь есть
этапы открытия редактора и подключения кнопки. Предыдущая правка `toVString()` сохранена.

Первая версия Geode-мода для **Geometry Dash 2.2081 / Windows x64 / Geode 5.10.1**.
Импортирует макрос Silicate, строит временную карту нажатий и добавляет обычные
Options Triggers в редактор. Созданные объекты сохраняются в уровне; для их
работы HoldForge у игрока не требуется.

**Статус:** исходники готовы для первой сборки и игрового тестирования. Парсер и
планировщик проверены локально с AddressSanitizer/UndefinedBehaviorSanitizer.
Полная Windows-сборка, внешний вид меню в GD, точность срабатывания и прохождение
hold-версии ещё не проверены. Это beta, а не подтверждённый frame-perfect конвертер.

## Как собрать через GitHub Actions

1. Распакуй архив. Загрузи **содержимое** папки `holdforge` в корень своего GitHub
   репозитория: `CMakeLists.txt`, `mod.json`, `src`, `tests`, `.github` и остальные файлы.
   Не пропусти скрытую папку `.github`.
2. Открой **Actions → Build HoldForge → Run workflow**. Сборка также стартует при push.
3. Workflow сначала запускает тесты, затем собирает Win64 под SDK **5.10.1** с
   закреплённой ревизией bindings для **2.2081**.
4. В успешном запуске скачай артефакт **HoldForge-Win64**. Положи полученный `.geode`
   в `Geometry Dash/geode/mods` и перезапусти игру. `.pdb` сохрани для разбора падений.
5. Если сборка упадёт, пришли лог **первого неуспешного шага** Actions целиком.

Workflow создаёт артефакт сборки. Он не публикует релиз и не требует твоего PAT.

## Использование

1. Сделай копию исходного уровня. Макрос должен быть записан **с начала уровня**,
   для этой же версии уровня, одной чистой попыткой. У `.slc` нет надёжной привязки
   к ID и геометрии уровня — автоматически проверить совпадение нельзя.
2. В редакторе останови playtest и воспроизведение музыки. Нажми **HF** слева
   примерно посередине экрана. Пауза для открытия HoldForge больше не нужна.
3. **Import .slc** выбирает файл и запускает анализ. В меню показаны версия формата,
   TPS, число триггеров и полосы удержания P1/P2. **Help** показывает замечания анализа.
4. В **Settings** можно изменить смещение времени, X, ряд Y, слой редактора и отладку.
   После изменения нажми **Analyze**. Перед **Create** анализ также повторяется.
5. Нажми **Create**. Объекты добавляются одной Undo-операцией и выделяются.
   По умолчанию они лежат на editor layer **999**, Y = **90**.
6. Тестируй с начала: держи ввод P1 постоянно. В **2 Player Mode** нужно постоянно
   держать оба соответствующих ввода. Выключи воспроизведение макроса в Silicate
   на время проверки полученной hold-версии.
7. Сохраняй уровень после теста. Повторный импорт по умолчанию остановится,
   если в уровне уже есть Options-триггеры управления: сначала сделай Undo.

## Механика Options Trigger

Options имеет ID **2899**. Настройка — трёхсостояние, а не bool:

| Событие | P1: property 165 | P2: property 199 | Смысл |
| --- | ---: | ---: | --- |
| До первого нажатия | `1` | `1` | Блокировать ввод |
| Нажатие в макросе | `-1` | `-1` для общего ввода | Разрешить уже удерживаемый ввод |
| Отпускание в макросе | `1` | `1` для общего ввода | Заблокировать ввод |
| Состояние игрока не меняется | `0` | `0` | Не трогать его настройку |

В bindings Geode это `GameOptionsSetting::On = 1`, `Off = -1`,
`Disabled = 0`. **Disabled здесь значит «не менять настройку», а не «блокировать
игрока».** Ошибка в этом месте делает всю генерацию неверной.

Для обычного dual поток P1 зеркалируется в обе настройки управления. В 2-player
потоки независимы, одновременные изменения P1/P2 объединяются в один Options.
Если в 2-player у P2 нет событий, его управление остаётся заблокированным;
анализ показывает предупреждение. Отличающийся поток P2 при выключенном
2 Player Mode отклоняется, а не теряется молча.

Options разрешает/запрещает управление, а не воспроизводит произвольную кнопку.
Результат зависит от удерживаемого физического ввода и поведения текущего режима
игры. Cube, ship, wave, ball, UFO, robot, spider, swing и взаимодействие с орбами
нужно проверить в игре. Начальный триггер может требовать калибровки у самого старта.

## Точность и текущие границы

- Координаты вычисляются через **`LevelEditorLayer::posForTime`**, с проверкой
  обратного `timeForPos`. Это карта редактора с учётом его speed-порталов,
  а не формула `frame × постоянная скорость` и не симуляция реального прохождения.
- По умолчанию разрешено только **240 TPS**. Опция Strict 240 TPS может быть снята:
  тогда изменения TPS интегрируются по участкам времени, но соответствие физики
  исходному боту не гарантируется.
- `Timing offset (ms)` сдвигает события макроса; положительное значение означает
  позже. Начальный блок остаётся в t=0. `Position offset` двигает все триггеры.
- Нажатие и отпускание в одном кадре, в том числе `.slc` **swift**, не преобразуются:
  пара Options в одной координате ненадёжно передаёт такой ввод.
- Restart, RestartFull, Death, Bugpoint и Left/Right блокируют генерацию.
  Нужен чистый classic-макрос, не platformer и не запись нескольких попыток.
- Reverse, Arrow/rotation, Teleport, Dash, TimeWarp, Gameplay Offset и Player Control
  по умолчанию останавливают статическую конверсию. **Experimental timeline**
  разрешает попытку с предупреждением. Результат при этих механиках может быть
  неправильным; повторяющийся/обратный X отклоняется всегда.
- Динамическое движение порталов, spawn/toggle условий, random-триггеры,
  отличающиеся траектории P1/P2 и custom physics других модов не моделируются.
  Проверка известных объектов и обратного времени не доказывает точность прохождения.
- Seed читается и логируется, но рандом уровня не переписывается.
- Прежний формат без сигнатуры не угадывается: переэкспортируй его в Silicate v2/v3.
- Ограничения чтения: 16 MiB, 1 000 000 распакованных событий, до 1 часа времени;
  генерация — 20 000 объектов по умолчанию, максимум 50 000 через Settings.

Следующий шаг для сложных 2.2-уровней — режим записи фактической траектории
при воспроизведении макроса. Полная автоматическая запись траектории пока отсутствует; 0.1.3 умеет применять проверенный sidecar `.hftrace`.

## Логи для разбора ошибки

В **Settings → Advanced Debug** включи:

| Настройка | Что попадёт в отчёт |
| --- | --- |
| Enable diagnostic journal | Журнал и экспорт диагностики |
| Log decoded macro inputs | Кадры, кнопки, P1/P2, press/release, TPS |
| Log time-to-position mapping | Время, координаты и обратная проверка каждого триггера |
| Trace playtest inputs and triggers | Options до/после, ввод и буферы, dual-переходы, режимы, смерти/сбросы в PlayLayer и damage в редакторе |
| Include generated object strings | Строки сериализации созданных объектов |
| Include mod versions | ID, версии и состояние загрузки установленных модов |
| Diagnostic event limit | Ограничение объёма журнала |

После изменения настроек заново импортируй макрос, воспроизведи проблему,
открой HoldForge → **Export logs**. Откроется папка с `holdforge-….json` — пришли
этот **один файл**. При проблеме соответствия уровню приложи ещё исходный `.slc`
и копию уровня: отчёт не включает полный уровень и исходный бинарник.

Если игра упала, до следующего импорта сохрани `latest.jsonl`; после перезапуска
предыдущая сессия находится в `previous.jsonl`. Приложи также crash log Geode,
если он появился. Journal сбрасывается при импорте; записывает первые N событий.
JSON-экспорт содержит последние N событий и счётчик вытесненных записей.
Отладочный файл не является дампом памяти и не содержит автоматический stack trace.

Файлы находятся в подпапке `diagnostics` каталога сохранения мода
(`Mod::get()->getSaveDir()`; фактический путь открывает Export logs).
Raw-снимки до вставки находятся рядом в `backups/`. Они имеют формат строки уровня,
**не** `.gmd`/`.gmd2`. Для обычного отката используй Undo; backup предназначен для
ручного восстановления/разбора. Мод не сохраняет изменения уровня автоматически.

## Проверки и структура

`src/core/Slc.*` — независимый bounds-checked бинарный парсер.
`src/core/Plan.*` — события, время, независимые/общие потоки.
`src/Editor.*` — карта редактора, защита от конфликтов, вставка/проверка/Undo.
`src/HoldPopup.*` — native Cocos2d/Geode UI; ImGui не используется.
`src/Diagnostics.*` — отчёты; `src/main.cpp` — launcher, trace hooks и runtime-поправка shared dual.
`src/core/HeldInput.hpp` — состояние реального ввода; `src/core/Calibration.*` — проверка и чтение записанных позиций.

Локально проверено: **1553 assertions/checks** и **2000 детерминированных мутаций**
бинарных данных. ASan/UBSan прошли; LeakSanitizer отключён из-за ограничений среды
запуска. Проверки охватывают v2/v3, все ширины входов, repeats, swift, specials,
все обрезанные префиксы валидных файлов, TPS, dual/2P и причины отказа генерации.
Парсер проверен на синтетических файлах. Для 0.1.2 разобраны журналы пользователя с 412 событиями; в 0.1.3 дополнительно проверен присланный бинарный `.slc`; уровень не предоставлялся. Полная Windows-сборка и игровой тест этой версии выполняются через Actions и в GD соответственно.

Запуск тестов без GD и Geode:

```sh
cmake -S . -B build-tests -DHOLDFORGE_CORE_ONLY=ON
cmake --build build-tests
ctest --test-dir build-tests --output-on-failure
```

Источники, форматы и план игрового тестирования — [docs/RESEARCH.md](docs/RESEARCH.md)
и [docs/IN_GAME_TESTS.md](docs/IN_GAME_TESTS.md).
